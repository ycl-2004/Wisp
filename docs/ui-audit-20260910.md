## Requirements

1. Check the current UI against the existing compact-panel style and earlier requirements.
2. Preserve the floating island, compact panel, input outline, and status chips.
3. Review information density and the newly added Commands surface.
4. Check customer-facing settings, help text, and English / Simplified Chinese localization.
5. Verify the changes, commit, and push the current branch.

## Findings and changes

The existing direction remains appropriate: a native macOS utility with restrained glass,
semantic colors, small SF Symbols, and shared `DS` typography, spacing, and corner radii.
This is a refinement of that system, not a new visual direction. The local design-reference
routing identifies `linear.app` as a useful density/hierarchy reference; no brand styling
or website interaction patterns were adopted.

The screenshot's header was crowded primarily because the model menu used `fixedSize()`.
That asks SwiftUI to preserve the ideal content size, allowing a long connection/model
label to squeeze the capture-status labels. The model menu now yields space and displays
the effective model alone. Its menu and tooltip retain the connection information, and
its accessibility label retains the complete description. Conversation counts keep their
width; long application names can truncate. Status chips remain single-line and retain
their outlines. The native menu has an explicit width based on the panel width so its
intrinsic size cannot displace the counters. The page-text chip shows a document icon and
character count; its full description and truncation status remain in help and accessibility
text. Very long model names deliberately truncate in the compact panel.

Source: [Apple — fixedSize](https://developer.apple.com/documentation/swiftui/view/fixedsize()).

Commands reuse the existing suggestion chips and the Settings information popover. Their
name, response mode, shortcut and question are the necessary visible controls. Explanatory
copy stays in the information popover. Blank/whitespace names now display “Untitled” in
the list, command menu and suggestion chips. Add/delete buttons and the question editor
have explicit accessibility labels. The editor uses `DS.body`, the inherited settings
background and a shared hairline outline instead of a contrasting white rectangle.

The floating island and its idle/hover/generating geometry remain present. The panel's
outer rim, input outline and chip borders remain present. The existing 140pt collapsed
height, multiline growth and voice-row Quick/Deep controls remain the baseline.

Customer-facing static strings in Commands, response settings and general Settings were
checked against the string catalog. The relevant Commands strings have both English and
Simplified Chinese translations; language-picker self-names remain in their own language.
Endpoint, executable and model details are available through information controls for
connection troubleshooting. They are not always-visible explanatory paragraphs.
