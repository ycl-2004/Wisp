# Wisp

按快捷键唤起一个悬浮小窗，让 AI 读取你**当前屏幕的上下文**回答问题。用你自己的 API Key。

和「只截一张图」的工具不同：在浏览器里，它会连**整页正文**一起发给模型，不只是可见的那一屏。

## 它做什么

```
按 ⌃⌥Space
  ↓ 记住当前前台应用（浮窗出现之前）
  ↓ 并行：截当前窗口的图  +  如果是浏览器，取网址、标题、整页正文、选中文字
  ↓ 浮窗出现，头部写清这次会发送什么
  ↓ 提问 → 流式回答
  ↓ 关掉浮窗，聊天文字留着；截图不落盘
```

明确不做：主动提醒、自动点击输入、长期人物画像、向量数据库、云同步、后台持续录屏。

## 首次设置

### 1. 屏幕录制权限

系统设置 → 隐私与安全性 → 屏幕录制 → 打开 **Wisp**。
**打开之后必须退出 Wisp 再重新打开**，macOS 才会让新权限生效。

macOS 15 以后每个月会再问一次「是否继续允许录屏」，这是系统行为。

### 2. 自动化权限

第一次读浏览器时会弹「Wisp 想要控制 Google Chrome」，点允许。
之后可在系统设置 → 隐私与安全性 → 自动化 里改。

### 3. 浏览器的 JS 开关（读整页文字必需）

- **Chrome 系**：菜单栏 View → Developer → **Allow JavaScript from Apple Events**
- **Safari**：Develop → **Allow JavaScript from Apple Events**

**这个开关在 Chrome 里是「每个配置文件各自独立」的。** 你有几个配置文件在用，就要在每个配置文件的窗口里各打开一次。
没打开的配置文件只能读到网址和截图，读不到整页文字。

打开 Wisp 设置的「屏幕与权限」页，可以看到每个配置文件当前的状态。

### 4. 选一种接法

菜单栏图标 → 设置 → 模型页，三选一。

**云端接口**（任何 OpenAI 兼容接口）
- Base URL：默认 `https://api.openai.com/v1`。OpenRouter 填 `https://openrouter.ai/api/v1`
- 模型：下拉选。认出是 OpenRouter 或 OpenAI 时会给三个推荐，选「自定义」才需要自己填
- API Key：存在 macOS 钥匙串，不写进对话文件

**Ollama 本地**
- 模型跑在本机，不联网也不花钱，也不用 Key
- Base URL 默认 `http://localhost:11434/v1`
- 模型清单直接读自本机 Ollama，标了「可读图」的才能看截图
- Ollama 没运行时页面上会有「启动 Ollama」按钮
- 装个视觉模型：`ollama pull minicpm-v4.6`

**Codex CLI**
- 复用你已经登录的 Codex，不用另配 Key
- 模型下拉，清单直接读自 `~/.codex/models_cache.json`，默认跟随 Codex 自己的设置
- 以只读沙箱运行，不落会话文件
- 两个代价：每次带约两万 token 的固定上下文，走你的 Codex 额度；没有逐字流式，回答一次性出现

### OpenRouter 上推荐哪几个

| 模型 | 输入 $/百万 | 上下文 | 适合 |
|---|---|---|---|
| `z-ai/glm-5.3-flash` | 0.075 | 131 万 | 默认，综合最稳 |
| `qwen/qwen3.7-flash` | 0.030 | 100 万 | 最便宜的实用款 |
| `minimax/minimax-m3:free` | 免费 | 100 万 | 免费首选 |
| `thinkingmachines/inkling:free` | 免费 | 100 万 | 免费备用，最强也最挤 |

三种都点「保存并测试连接」。前两种会发一张 64×64 小图，同时验证连通性、模型名和图片输入支持；Codex 只检查能不能跑起来。

## 两种形态

平时你只会看到一颗**小药丸**，浮在屏幕底部正中、Dock 上方。

| 状态 | 样子 |
|---|---|
| 闲置 | 40×40 的一颗图标。颜色说明当前能读到什么：蓝色能读整页正文，灰色只能截图，橙色是被排除的应用 |
| 悬停 | 展开成 320×44 的一条，显示当前应用、能读什么、快捷键提示 |
| 生成中 | 340×48，柔和流光背景，右侧一个停止键 |
| 点一下 | 打开完整浮窗，药丸自动收起 |

药丸**只跟踪当前是哪个应用**，不截图，也不跑浏览器脚本。闲置时它不产生任何屏幕内容，符合「按需抓取」的原则。图标是静止的，不会跟着你切应用闪。

设置的「屏幕与权限」页可以关掉，或者改成**贴住刘海**的形态：闲置时只让刘海看起来宽 44pt，悬停才向两侧张开并向下长出一小块。没有刘海的屏幕会退化成顶部小胶囊。

## 用法

浮窗默认 420×480，在屏幕底部居中，背景是毛玻璃，能看见下面的内容。**底边固定，向上展开**：输入框位置不动，内容从上方长出来。可以拖动、可以拉伸，位置会记住，超出屏幕会自动夹回来。

| 操作 | 说明 |
|---|---|
| ⌃⌥Space | 唤起／收起浮窗（可在设置里改） |
| ⌘↩ | 发送 |
| ⌘. | 停止生成 |
| Esc | 收起浮窗 |
| 头部 ∧ | 收起成一条，只留头部和输入框。底边不动，向上收合。发送时自动展开 |
| 头部 ↻ | 手动重新读取（平时不需要，见下） |
| 点「截图」标签 | 这次要不要附截图 |
| 点 ⓘ 标签 | 展开本次采集的说明 |
| 头部 ☰ | 对话列表 |

### 上下文是自动读的

不用手动点刷新。三种情况会自动重新读取当前画面：

1. 唤起浮窗时。
2. **浮窗开着的时候你切到别的应用**，它会跟着切过去读新的画面。
3. 发送前，如果上一次读取已经超过 20 秒，或者中途你离开过浮窗。

生成回答的过程中不会自动重读，免得打断。画面和网址都没变时不会重复发同一张截图，省钱。

### 头部两行读什么

```
☰  [图标] Google Chrome  openrouter.ai/activity      ↻  ✎  ∧
   截图 · 正文 1417 字 · ⓘ1                2/30 轮 · 1/10 对话
```

第一行是现在在读哪个页面，第二行是这次会发送什么加上计数。原来那一大块提示压进了 ⓘ 里，点开才展开。

## 上限规则

- 最多 **10 个对话**。到上限「新建」按钮就禁用，必须先手动删一个。
- 每个对话最多 **30 轮**。到上限要新建或删除。
- **不按时间自动淘汰，不做隐形清理。** 删除是永久的，没有回收站。

两个数字都能在设置的「数据」页里改。

## 上下文怎么发给模型

- 每轮用户消息前面挂一个「屏幕上下文」块：应用、窗口标题、网址、页面标题、选中文字、整页正文。
- **只有最近 2 轮保留完整上下文**，更早的折叠成一行摘要。
- **历史里的截图不重发**，只发本轮的。同一份上下文在同一对话里也只发一次截图。
- 整页正文超过上限（默认 60000 字）会保留头 75% 和尾 25%，中间标注省略了多少字。

这样单次请求的 token 上限是可预期的，不需要任何总结或向量检索。

## 存哪里

```
~/Library/Application Support/Wisp/
├── conversations.json      对话文字 + 页面文字快照
└── debug/                  仅在设置里打开调试时才有
```

- **截图从不写入硬盘**，只在内存里，发完就释放。
- API Key 在钥匙串，不在这个目录里。
- 设置的「数据」页有「删除全部对话与 API Key」。

诚实说明：这只保证从应用可访问的数据里删除。Time Machine 备份、APFS 快照、模型供应商那边的请求日志，本应用管不到。

## 已知限制

- **跨域 iframe 的正文读不到**，只能靠截图。浮窗会提示页面里有几个这样的框架。
- 浏览器内部页面（`chrome://` 等）读不到正文。
- 非浏览器应用只有截图，没有整页文字。
- Chrome 的 JS 开关分配置文件，见上面第 3 步。

## 开发

```bash
xcodegen generate
xcodebuild -project Wisp.xcodeproj -scheme Wisp -configuration Debug build
cp -R Build/Debug/Wisp.app ~/Applications/
```

用 Apple Development 证书签名（Team `BQYHJCCRMP`），签名标识稳定，所以重新编译一般不会让授权失效。

### 诊断入口

```bash
# 跑一次采集，打印结果并写到 debug 文件夹
~/Applications/Wisp.app/Contents/MacOS/Wisp --dump-context

# 远程唤起浮窗，不用按快捷键
~/Applications/Wisp.app/Contents/MacOS/Wisp --show
```

注意：直接跑二进制时，进程是终端的子进程，**录屏权限会算在终端头上**，看到的结果可能比 Wisp 自己跑更宽松。要测 Wisp 真实的权限状态，用：

```bash
open -g -n -a ~/Applications/Wisp.app --args --dump-context
```

## 代码结构

| 目录 | 内容 |
|---|---|
| `App/` | 入口、菜单栏、全局快捷键、诊断入口 |
| `Capture/` | 截图、浏览器取文、Chrome 配置文件检测、采集编排 |
| `LLM/` | 三种接法：OpenAI 兼容 HTTP、Ollama、Codex CLI；SSE 解析、提示词组装 |
| `Store/` | 对话 JSON、钥匙串 |
| `UI/` | 悬浮面板、聊天、上下文头部、对话列表、设置 |
| `UI/DesignKit.swift` | 尺寸圆角字号、毛玻璃、悬停按钮、状态标签 |
| `UI/MarkdownText.swift` | 轻量 Markdown 渲染，无第三方依赖 |
| `UI/Island*.swift` | 灵动岛：常驻窗口、视图、当前应用跟踪 |
| `Support/ScreenGeometry.swift` | 刘海检测与灵动岛定位 |
